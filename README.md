# План / Факт

Рабочий MVP Telegram Mini App и web-приложения для ежедневного производственного контроля строительных объектов. Оба интерфейса используют один API и набор раздельных JSON-хранилищ.

## Что реализовано

- роли **Администратор**, **Руководитель**, **Ответственный** в разрезе объекта;
- переключение объектов и изоляция данных;
- web-вход и серверная проверка Telegram Mini App Init Data;
- настраиваемый ежедневный отчёт: работы, люди, механизмы, фото, проверка;
- серверная проверка доступного остатка непосредственно перед сохранением;
- План / Факт за день, 3 дня, 7 дней и месяц;
- фильтры по подрядчику и работе, отбор и сортировка отставаний;
- накопительная аналитика, календарь и контрольные вехи;
- отчёты по людям, технике и фотографиям;
- настраиваемый Excel-импорт XLSX/XLSB, JSON-представление, версии и архив месяцев;
- выгрузка факта в ячейки сохранённого оригинального Excel;
- управление объектами, организациями и пользователями;
- журнал критических действий;
- адаптивный desktop/mobile интерфейс.

Подробные правила расчёта и критерии приёмки именно веб-раздела описаны в [WEB_PLAN_FACT_SPEC.md](WEB_PLAN_FACT_SPEC.md). Интеграция с Telegram в эту спецификацию не входит.

## Локальный запуск

Требуются Node.js 18+ и Python 3. Зависимости для чтения Excel установите перед запуском:

```powershell
python -m pip install -r requirements.txt
```

```powershell
npm start
```

Для постоянной работы локального сервиса в Windows установите задачу автозапуска. Она запускает приложение при входе пользователя и автоматически перезапускает его при завершении или зависании:

```powershell
powershell -ExecutionPolicy Bypass -File tools\install_local_service.ps1
```

Откройте [http://127.0.0.1:4173](http://127.0.0.1:4173).

Первоначальная учётная запись:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Администратор | `Пархоменко` | `286` |

Синтаксическая и быстрая интеграционная проверка:

```powershell
npm run check
npm run smoke
```

## Telegram Mini App

1. Разместите приложение на HTTPS-домене. Боевой адрес — `https://bimmax.pro/planfakt/`; порядок размещения на сервере описан в репозитории портала: `deploy/plan-fakt/README.md`.
2. Укажите этот же адрес как Web App URL в BotFather — **в двух местах**: `Bot Settings → Menu Button` и `/myapps → Edit link`.
3. Задайте на сервере `TELEGRAM_BOT_TOKEN` и публичный HTTPS-адрес `WEB_APP_URL`.
4. Пропишите тот же адрес порталу: в `.env` сайта `bimmax.pro` строкой `PLAN_FACT_APP_URL=https://bimmax.pro/planfakt/` — по нему раздел «План/факт» открывает приложение.
5. Привяжите уникальный Telegram ID к пользователю в админ-разделе.

Частая ошибка: в BotFather попадает путь к файлу настроек (`https://bimmax.pro/.env`) или адрес главной страницы портала. По сети такой файл закрыт, и Telegram показывает главную страницу сайта вместо приложения. Приложение отклоняет такие адреса при запуске и пишет причину в журнал.

После заполнения `WEB_APP_URL` настройте и проверьте кнопку бота одной командой:

```powershell
npm run telegram:configure
```

Перед изменением Telegram команда запрашивает `${WEB_APP_URL}/api/health` (с учётом подпапки) и требует ответ `{ "ok": true, "service": "plan-fakt" }`. Поэтому адрес главной страницы портала, `127.0.0.1`, `bmsu4.php` и `bmsu-4.php` больше не могут быть ошибочно записаны как Mini App. После изменения команда повторно читает кнопку через Telegram API. Если у бота включён Main Mini App, его отдельную ссылку также необходимо заменить через `@BotFather` → `/myapps` → `Edit link`.

`WEB_APP_URL` должен вести прямо на это приложение (страницу `public/index.html` через запущенный `server.js`). Страница портала `bmsu4.php` тоже работает как точка входа — она переносит данные запуска Telegram в приложение, — но прямой адрес быстрее и надёжнее. Тот же адрес укажите в BotFather как URL главного Mini App. После запуска сервер автоматически обновит кнопку меню бота.

Приложение разрешает открывать себя во фрейме только порталу из `BMSU_SITE_ORIGINS` и клиентам Telegram (`Content-Security-Policy: frame-ancestors`): без этого Telegram Desktop и web-версия показывали пустое окно.

При каждом открытии внутри Telegram клиент передаёт `initData`, а сервер проверяет HMAC-подпись, срок действия и ищет подтверждённый Telegram ID. Telegram ID от клиента без валидной подписи не принимается.

Сервер также запускает самого бота в режиме long polling. Доступны команды `/start`, `/app`, `/id` и `/help`. Если `WEB_APP_URL` задан, `/start` и постоянная кнопка меню открывают Mini App. При неизвестном Telegram ID приложение предлагает войти по логину и паролю и отдельно подтвердить привязку. Сервер привязывает только ID из проверенного Telegram Init Data.

Сценарии входа разделены:

- на обычном сайте при каждом открытии сначала показывается форма логина и пароля; сохранённая cookie не открывает интерфейс автоматически;
- в Telegram сначала показывается состояние проверки ID, а само приложение остаётся закрытым;
- найденный Telegram ID открывает именно связанный с ним аккаунт и игнорирует сохранённый маршрут или hash старой страницы;
- если аккаунту назначен один объект, он открывается без дополнительного экрана; если активных объектов несколько, Telegram показывает выбор с названием заказчика, ролью и списком подрядчиков;
- для администратора и руководителя сразу открывается раздел «План / Факт», для ответственного — главная страница его объекта;
- неизвестный ID открывает форму логина и пароля с обязательным отдельным подтверждением привязки;
- при недействительной подписи или просроченных данных Telegram вход и привязка блокируются.

## JSON-хранилища

Данные разделены по назначению и сохраняются атомарно в каталоге `data`: `users.json`, `telegram-links.json`, `projects.json`, `organizations.json`, `works.json`, `reports.json`, `schedules.json`, `milestones.json`, `dictionaries.json`, `audit.json` и `meta.json`. Пароли представлены только криптографическими хешами. Telegram ID хранится вместе с учётной записью в `users.json`; `telegram-links.json` оставлен как автоматически синхронизируемый индекс совместимости.

`users.json` хранит все учётные записи, Telegram ID, полное название организации пользователя и его назначения на объекты. В каждом назначении записаны роль, организация пользователя, доступные подрядчики и полное/портальное название организации-заказчика. `projects.json` хранит все объекты; каждый объект содержит `customerOrganization` с именем страницы портала и `contractorIds` — свой список подрядчиков.

При первом запуске старый `data/store.json`, если он существует, автоматически читается и мигрируется в эти файлы. После успешной миграции старый файл можно оставить как резервную копию: приложение больше не записывает в него.

## Размещение сайта

Создайте `.env` по образцу `.env.example`, обязательно замените секреты, затем запустите:

```powershell
docker compose up -d --build
```

Для публичного доступа разместите перед приложением reverse proxy с HTTPS (Nginx, Caddy или облачный ingress). Каталог `/app/data` вынесен в постоянный Docker volume.

Приложение работает и в корне домена, и в подпапке: страницы, скрипты и запросы к API строятся относительно адреса приложения. Поэтому отдельный поддомен и новая запись DNS не нужны — достаточно подпапки уже существующего сайта:

```nginx
location /planfakt/ {
    proxy_pass http://127.0.0.1:4173/;   # слэш в конце срезает префикс
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 64m;
}
```

Готовый файл конфигурации и служба systemd лежат в репозитории портала: `deploy/plan-fakt/`. Адрес всегда со слэшем на конце — без него браузер ищет файлы приложения в корне сайта.

### Переход из карточки на сайте

Файл `bmsu4.js` (копия того, что лежит на портале по пути `public_html/js/other/bmsu4.js`) открывает компактное модальное окно входа поверх текущей страницы сайта. После успешной проверки логина сервер выдаёт одноразовый билет на 60 секунд; приложение обменивает его на защищённую сессию, удаляет билет из адресной строки и сразу открывает интерфейс.

Страница `bmsu4.php` осталась как точка входа для Telegram: параметры запуска Mini App приходят во фрагменте адреса и на сервер не попадают, поэтому решение принимает браузер. Страница показывает «Открываем раздел…», переносит эти параметры и уходит в приложение. Сессия портала для неё не нужна — вход проверяет само приложение.

На локальном стенде используется `http://127.0.0.1:4173/`: перед проверкой перехода запустите приложение командой `npm start`. Локальный fallback теперь включается только если сама страница открыта на `localhost`/`127.0.0.1`; публичная страница больше не будет ошибочно отправлять мобильного пользователя на его собственный `127.0.0.1`. Адрес `bimmax.pro:4173` не используется — этот порт недоступен извне. Для боевого размещения сначала опубликуйте приложение через HTTPS reverse proxy, а затем задайте его публичный адрес перед подключением файла:

```html
<script>
  window.PLAN_FACT_APP_URL = 'https://bimmax.pro/planfakt/';
</script>
<script src="js/other/bmsu4.js"></script>
```

Альтернативно адрес можно передать атрибутом `data-app-url` у тега `script` или `data-plan-fakt-url` у `body` — именно так его подставляет `bmsu4.php`, читая `PLAN_FACT_APP_URL` из `.env` портала. Если адрес не задан ни одним способом, публичная страница не переходит никуда, а честно показывает «Раздел ещё не подключён».

Список сайтов, которым разрешено обращаться к форме входа и открывать приложение во фрейме, задаётся переменной `BMSU_SITE_ORIGINS` через запятую. По умолчанию разрешён `https://bimmax.pro`.

## Excel-шаблон

Администратор загружает `.xlsx` или `.xlsb` в разделе «Загрузить таблицу» и перед импортом явно задаёт:

- лист и первую строку данных;
- колонки номера, кода, наименования, организации и единицы измерения;
- объём по проекту, выполненный объём до начала месяца, остаток и план на месяц;
- любое количество колонок иерархии: блок, подблок, этап и последующие уровни;
- колонку признака `План/Факт`, значение строки плана, смещение строки факта и колонку первого дня месяца.

Для ведомости `СМГ Упрощённый.xlsb` готовый пример сопоставления находится в `tools/smg_mapping.example.json`: данные начинаются со строки 3, иерархия расположена в C/D/E, работа — в F, организация — в G, показатели — в J:M, признак строки — в N, дни месяца начинаются с O.

Исходный файл хранится отдельно. При экспорте исходный `.xlsx` копируется и дополняется фактом; для двоичного `.xlsb` формируется новый `.xlsx` «План-Факт» с той же структурой работ и дневными значениями.

Для нестандартного корпоративного шаблона правила распознавания находятся в `tools/excel_bridge.py` и могут быть адаптированы без изменения API.

## Настройки организации

В едином разделе «Администрирование» находятся объекты, пользователи и организации. Для каждой организации можно включить сбор данных по людям/профессиям, механизмам и фотофиксации. План-факт по работам является обязательной основой отчёта. Отключённые разделы не только скрываются в интерфейсе, но и не принимаются сервером при сохранении отчёта.

## Переход к промышленной эксплуатации

Текущий MVP намеренно запускается без внешней СУБД и хранит каждый тип данных в отдельном JSON-файле каталога `data`. Перед эксплуатацией с несколькими одновременными инстансами следует заменить файловый адаптер на PostgreSQL с транзакцией и блокировкой строки работы, фотографии вынести в S3-совместимое хранилище, а вход связать с корпоративным IdP. API и модель интерфейса уже разделены, поэтому эта замена не требует создавать два отдельных приложения.
