# Веб-раздел «План / Факт»

## Назначение и границы

Раздел даёт руководителю и администратору проверяемый срез выполнения производственного графика на выбранную дату. Эта спецификация относится только к сайту: Telegram Mini App, бот, привязка Telegram ID и мобильные сценарии в объём работ не входят.

## Источники данных

- План берётся из активного загруженного производственного графика и хранится по каждой работе и календарной дате.
- Факт берётся только из отправленных ежедневных отчётов со статусом `sent`.
- Работа однозначно относится к объекту, подрядчику и единице измерения.
- Дата по умолчанию определяется в часовом поясе выбранного объекта.

## Расчёты

Для каждой работы рассчитываются отдельно:

- план периода — сумма дневного плана от начала выбранного периода до даты среза включительно;
- факт периода — сумма факта за тот же интервал;
- отклонение периода = факт периода − план периода;
- накопительный план — сумма плана с начала графика до даты среза включительно;
- накопительный факт — сумма факта с начала ведения данных до даты среза включительно;
- накопительное отклонение = накопительный факт − накопительный план;
- выполнение = накопительный факт / накопительный план × 100%; при нулевом плане процент не рассчитывается;
- остаток = общий объём − накопительный факт, но не меньше нуля.

Объёмы с разными единицами измерения не складываются. Сводные объёмы формируются отдельно для каждой единицы: м, м², м³, т и т. д.

## Статусы

- **Отставание** — накопительный факт меньше накопительного плана.
- **В графике** — накопительный факт равен накопительному плану.
- **Опережение** — накопительный факт больше накопительного плана.
- **Нет плана** — к дате среза план равен нулю и факт отсутствует.
- Факт при нулевом плане считается опережением, но процент выполнения не показывается.

Сравнение объёмов выполняется с техническим допуском `1e-9`, чтобы ошибки представления дробных чисел не создавали ложное отставание.

## Фильтры и сортировка

- Периоды: сегодня, последние 3 дня, последние 7 дней, месяц с первого числа по дату среза.
- Дата среза включается в расчёт.
- Подрядчик ограничивает список работ; при его смене выбранная работа сбрасывается.
- Работа относится только к текущему объекту.
- Фильтр «Только отставания» использует накопительный статус.
- Сортировка: сначала максимальное отставание, по проценту выполнения или по названию.
- При смене объекта фильтры подрядчика, работы, даты и отставаний сбрасываются.

## Доступ

- Раздел и API аналитики доступны ролям `manager` и `admin` в рамках назначенного объекта.
- Пользователь без назначения на объект получает отказ `403`.
- Идентификаторы подрядчика и работы проверяются на принадлежность объекту.
- Некорректные даты, неизвестные периоды, обратный интервал и интервал длиннее 366 дней отклоняются с `400`.

## Состояния интерфейса

- Во время загрузки показывается скелетон.
- При ошибке показываются текст причины и кнопка повторной загрузки.
- При пустом объекте предлагается загрузить производственный график.
- При пустом фильтре отставаний явно сообщается, что отставаний нет.
- Таблица прокручивается горизонтально на узких экранах и не скрывает столбцы.

## Критерии приёмки

1. Смена периода изменяет колонки периода, но не искажает накопительные значения.
2. Факт на границах интервала учитывается включительно и ровно один раз.
3. Выбор подрядчика не показывает работы другого подрядчика.
4. При выборе одной работы итог содержит только эту работу.
5. Разные единицы измерения представлены раздельными итогами.
6. Работа с планом 10 и фактом 8 имеет отклонение −2 и статус «Отставание».
7. Работа с нулевым планом и нулевым фактом имеет статус «Нет плана» и не получает 0% выполнения.
8. Дата по умолчанию соответствует часовому поясу объекта.
9. Недоступный объект возвращает `403`, чужая работа или подрядчик — `400`.
10. После отправки нового отчёта повторное открытие раздела показывает пересчитанный факт.

## Пока не входит в объём

- Telegram-вход и привязка Telegram ID;
- push-уведомления и бот-команды;
- offline-режим и синхронизация мобильного приложения;
- согласование и корректировка уже отправленного факта;
- денежные показатели и стоимостной план/факт.
